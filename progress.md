2026-08-21: cross-screen follow root cause corrected and window re-anchored to the true desktop union (adaptive).  The remaining "spider pins at the seam" was NOT a universal window-server refusal to span: whether a multi-screen borderless window honours a union request depends on the arrangement (some accept the union unchanged, others relocate it to the origin of the screen it most overlaps).  So no fixed arrangement can be assumed.  The real, reproducible defect was candidate order in `placeWindow`: `union@0,0` (a union anchored at the main-screen origin, x=0) came first and — because it also contains the main-screen centre — was accepted, offsetting the window permanently by the secondary's horizontal overhang so it missed that overhang and the spider could not reach a cursor there (pinned at the seam).  Fix: try the raw desktop union first (`NSRect(origin: union.origin, size: union.size)`) and accept a frame only when it covers the desktop union centre (fall back to main-screen coverage; force-accept the last candidate so a server that refuses every span still leaves a usable window).  This is purely adaptive — it reads the live screens and makes no assumption about any device's size or arrangement. 2026-08-22: desktop-pet now tracks the cursor exactly and crosses screens.  The real root cause of both "can't reach the other screen" and "doesn't track the mouse precisely" was the window-edge projection in `petPointer`: when the cursor sat inside any desktop window, the follow goal was snapped to that window's nearest edge (x=wx±14 etc.) instead of the cursor.
